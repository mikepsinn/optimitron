# Analysis Pipeline

## Source of truth

The web app is the product surface for analysis outputs.

- Production budget and policy artifacts are generated by [apps/optimitron/scripts/generate-web-data.ts](../apps/optimitron/scripts/generate-web-data.ts)
- Generated production data lives in:
  - [apps/optimitron/src/data/us-budget-analysis.ts](../apps/optimitron/src/data/us-budget-analysis.ts)
  - [apps/optimitron/src/data/us-policy-analysis.ts](../apps/optimitron/src/data/us-policy-analysis.ts)
  - [apps/optimitron/src/data/us-government-size-analysis.json](../apps/optimitron/src/data/us-government-size-analysis.json)
- Published legislation content lives in:
  - [content/legislation](../content/legislation)

## Commands

- Regenerate budget and policy data:
  - `pnpm --filter @optimitron/web run generate`
- Refresh government-size artifact into the app:
  - `pnpm --filter @optimitron/web run refresh:government-size`
- Draft legislation markdown:
  - `pnpm --filter @optimitron/web run draft:legislation`
  - This now performs a first-pass evidence synthesis over [packages/data/src/parameters/parameters-calculations-citations.ts](../packages/data/src/parameters/parameters-calculations-citations.ts) before bill drafting.

## Package boundaries

- `apps/optimitron`: production analysis scripts, generated artifacts, content loaders, and user-facing routes.
- `packages/opg` and `packages/obg`: canonical policy and budget contracts, including legislation-brief types for drafting pipelines.
- `packages/agent`: LLM-facing synthesis and drafting logic, including the typed legislation evidence bundle built from the parameter corpus.
- `content/legislation`: committed markdown drafts reviewed through normal GitHub PRs.
- `reports/site`: removed. Do not recreate a second static analysis site unless there is a deliberate deployment target for it.
